1. 두 코드 한눈에 보기

정답이 y = 2x + 1인 점 100개를 만들고, w와 b를 0에서 시작해 정답에 가깝게 맞추는 예제. 두 코드는 줄 단위로 대응.

Python · NumPy 
import numpy as np
from numpy.random import Generator

randomGenerator: Generator = np.random.default_rng(seed=7)
x = randomGenerator.uniform(-1, 1, 100)
y = 2 * x + 1 + randomGenerator.normal(0, 0.05, 100)

w, b, learning_rate = 0.0, 0.0, 0.1
for step in range(201):
    error = (w * x + b) - y
    loss = (error**2).mean()
    if step % 40 == 0:
        print(f"step {step:3d}  loss {loss:.4f}  "
              f"w {w:.3f}  b {b:.3f}")
    w -= learning_rate * 2 * (error * x).mean()
    b -= learning_rate * 2 * error.mean()

assert abs(w - 2) < 0.1 and abs(b - 1) < 0.1
Swift · MLX 
import Foundation
import MLX

let (xKey, noiseKey) = MLXRandom.split(key: MLXRandom.key(7))
let x = MLXRandom.uniform(low: -1, high: 1, [100], key: xKey)
let y = 2 * x + 1 + MLXRandom.normal([100], loc: 0, scale: 0.05, key: noiseKey)

var w: Float = 0, b: Float = 0
let learningRate: Float = 0.1
for step in 0...200 {
    let error = (w * x + b) - y
    let loss = (error * error).mean()
    if step % 40 == 0 {
        print(String(format: "step %3d  loss %.4f  w %.3f  b %.3f",
                     step, loss.item(Float.self), w, b))
    }
    w -= learningRate * 2 * (error * x).mean().item(Float.self)
    b -= learningRate * 2 * error.mean().item(Float.self)
}

precondition(abs(w - 2) < 0.1 && abs(b - 1) < 0.1)

NumPy 배열 연산: 반복문 없이 원소별로 계산

x는 숫자 100개짜리 배열(ndarray). 배열에 산술 연산을 하면 100개 원소 각각에 같은 연산이 적용됨. 그래서 for 문 없이 한 줄로 100개를 계산.

x = np.array([0.1, -0.5, 0.8])
2 * x + 1        # array([1.2, 0.0, 2.6])   원소마다 2를 곱하고 1을 더함
x * x            # array([0.01, 0.25, 0.64]) 같은 위치끼리 곱함

2 * x + 1에서 2와 1은 숫자 하나지만 배열 100개와 계산됨. 작은 쪽을 큰 쪽 모양에 맞춰 늘려서 계산하는 규칙이 브로드캐스팅. MLX도 같은 규칙을 따르므로 Swift 코드에서도 2 * x + 1이 그대로 동작.

3. 즉시 계산과 지연 계산

두 라이브러리의 가장 큰 차이. 함수 이름과 인자는 비슷하지만 언제 계산하느냐가 다름.

  • NumPy: (error**2).mean()의 결과는 이미 계산된 숫자(np.float64). 그대로 f-string에 넣을 수 있음.
  • MLX: (error * error).mean()의 결과는 "이렇게 계산하라"는 기록을 담은 MLXArray. .item(Float.self), print, eval(...)처럼 실제 값이 필요한 순간에 계산됨.

미뤄 두면 여러 연산을 합쳐 GPU에 한 번에 보낼 수 있어 큰 모델에서 빨라짐. 대신 Swift Float와 섞어 쓰려면 .item()으로 꺼내야 함.

4. 난수 생성기: rng와 key

NumPy np.random.default_rng(seed=7)

Generator 객체를 생성. 내부에 PCG64 알고리즘의 상태가 있고, 난수를 뽑을 때마다 이 상태가 앞으로 진행됨. 그래서 같은 rng로 uniform을 부른 다음 normal을 부르면 서로 다른 난수가 나옴.

rng = np.random.default_rng(seed=7)
rng.uniform(-1, 1, 3)   # 상태가 진행됨
rng.uniform(-1, 1, 3)   # 위와 다른 값

rng = np.random.default_rng(seed=7)
rng.uniform(-1, 1, 3)   # 첫 번째 결과와 같은 값 (시드가 같으므로)

np.random.seed(7) + np.random.uniform(...)처럼 전역 함수를 쓰는 옛 방식도 있지만, NumPy 문서는 지금처럼 default_rng로 생성기를 만들어 쓰는 방식을 권장.

MLX MLXRandom.key(7)와 split

MLX의 키는 상태가 없음. 같은 키를 넣으면 몇 번을 불러도 같은 값이 나옴. 그래서 서로 다른 난수가 필요하면 split으로 키를 쪼개서 각각 넘김.

key를 생략하면MLX도 전역 난수 상태를 써서 NumPy 옛 방식처럼 동작. 결과를 매번 똑같이 재현하고 싶을 때만 키를 넘기면 됨.
같은 시드, 다른 숫자NumPy(PCG64)와 MLX는 난수 알고리즘이 달라서 시드를 똑같이 7로 줘도 뽑히는 점이 다름. 그래서 두 프로그램의 loss 값이 조금 다르지만, 둘 다 w ≈ 2, b ≈ 1로 수렴.

5. uniform: 균등분포

주어진 구간 안의 모든 값이 같은 확률로 나오는 난수를 생성. 구간은 [low, high)로, 아래쪽 끝은 포함하고 위쪽 끝은 포함하지 않음. 코드에서는 x축 위치 100개를 −1부터 1 사이에 고르게 뿌리는 데 사용.

NumPy Generator.uniform

Generator.uniform(low=0.0, high=1.0, size=None)
인자의미코드에서 쓴 값
low구간의 아래쪽 끝 (포함)-1
high구간의 위쪽 끝 (포함 안 함)1
size몇 개를 뽑을지. 정수나 튜플. 생략하면 숫자 하나100
 
rng.uniform(-1, 1, 100)          # 위치 인자로 순서대로
rng.uniform(low=-1, high=1, size=100)  # 이름을 붙여도 됨
rng.uniform(size=(2, 3))         # [0, 1) 구간, 2×3 배열
rng.uniform()                    # 숫자 하나 (배열 아님)

6. normal: 정규분포

평균(μ) 근처 값이 가장 많이 나오고, 멀어질수록 드물어지는 종 모양 분포. 가우스 분포라고도 함. 전체 값의 약 68%는 μ ± σ 안에, 약 95%는 μ ± 2σ 안에 들어감.

코드에서는 σ = 0.05인 잡음을 더해 점들이 y = 2x + 1 직선에서 조금씩 벗어나게 만듦. 잡음 대부분이 ±0.1 안쪽. 잡음이 없으면 점이 완전한 직선 위에 놓여 실제 데이터와 달라지므로 일부러 흔들어 줌.

NumPy Generator.normal

Generator.normal(loc=0.0, scale=1.0, size=None)
인자의미코드에서 쓴 값
loc평균 μ, 종 모양 곡선의 중심0
scale표준편차 σ, 곡선의 폭. 0 이상이어야 함0.05
size몇 개를 뽑을지100

MLX MLXRandom.normal

public static func normal(
    _ shape: some Collection<Int> = [],
    type: (some HasDType & BinaryFloatingPoint).Type = Float.self,
    loc: Float = 0, scale: Float = 1,
    key: (some RandomStateOrKey)? = nil,
    stream: StreamOrDevice = .default
) -> MLXArray
인자 순서가 반대NumPy는 normal(0, 0.05, 100)처럼 평균, 표준편차, 개수 순서. MLX는 normal([100], loc: 0, scale: 0.05)처럼 모양이 맨 앞에 오고 나머지는 이름을 붙여 넘김. MLX의 loc, scale은 Float 숫자 하나만 받음.

7. mean: 평균

배열 원소들의 산술 평균을 계산. 축(axis)을 지정하면 그 방향으로만 평균을 냄.

[[5, 8],
 [4, 9]]
NumPy 
a = np.array([[5, 8], [4, 9]])

a.mean()                    # 6.5
a.mean(axis=0)              # array([4.5, 8.5])
a.mean(axis=1)              # array([6.5, 6.5])
a.mean(axis=1, keepdims=True)

MLX

a.mean()                    // 6.5 (0차원 MLXArray)
a.mean(axis: 0)             // [4.5, 8.5]
a.mean(axis: 1)             // [6.5, 6.5]
a.mean(axis: 1, keepDims: true)
// [[6.5], [6.5]]  모양 [2, 1]

keepdims(keepDims)는 평균을 내서 없어진 축을 크기 1로 남겨 둠. 결과를 원래 배열과 다시 계산할 때 브로드캐스팅이 맞아떨어지게 하려고 사용.

a - a.mean(axis=1, keepdims=True)   # 각 행에서 그 행의 평균을 뺌. 모양 (2,2) - (2,1) → (2,2)

8. 학습 루프에서 mean의 의미

예측값은 ŷᵢ = w·xᵢ + b, 오차는 eᵢ = ŷᵢ − yᵢ. 코드의 mean 세 번은 다음 세 식을 계산.

코드수학뜻
(error**2).mean()L = (1/N) Σ eᵢ²손실: 평균제곱오차(MSE). 정답과 얼마나 다른가
2 * (error * x).mean()∂L/∂w = (2/N) Σ eᵢ·xᵢw를 조금 키우면 손실이 얼마나 변하나
2 * error.mean()∂L/∂b = (2/N) Σ eᵢb를 조금 키우면 손실이 얼마나 변하나

기울기 식은 어디서 나왔나

L = (1/N) Σ (w·xᵢ + b − yᵢ)² 를 연쇄 법칙으로 미분.

  • w로 미분: 바깥 제곱에서 2·eᵢ, 안쪽 w·xᵢ에서 xᵢ가 나와 (2/N) Σ eᵢ·xᵢ
  • b로 미분: 바깥 제곱에서 2·eᵢ, 안쪽 b에서 1이 나와 (2/N) Σ eᵢ

기울기는 손실이 커지는 방향이므로 그 반대로 learning_rate만큼 이동.

w -= learning_rate * 2 * (error * x).mean()
b -= learning_rate * 2 * error.mean()
loss가 0이 되지 않는 이유데이터에 표준편차 0.05짜리 잡음을 섞었기 때문에, 정답 직선을 정확히 찾아도 오차 제곱의 평균은 σ² = 0.05² = 0.0025 근처에 남음. 실행 결과의 0.0026이 바로 그 값.
MLX에서 .item()을 자주 부르면지금 Swift 코드는 반복마다 .item()을 두 번 불러 GPU 결과를 기다림. 값 100개짜리 예제에서는 문제가 없지만, 큰 모델에서는 w, b도 MLXArray로 두고 스텝 끝에 eval(w, b)를 한 번만 부르는 방식을 사용.
